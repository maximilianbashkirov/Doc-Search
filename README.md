# Doc-Search

Модульный асинхронный сервис полнотекстового поиска по текстам документов с использованием **FastAPI**, **PostgreSQL** и **Elasticsearch**.

## Архитектурные особенности решения
1. **Предотвращение рассинхронизации данных:** Для каждого документа генерируется детерминированный `UUID5` на основе хэша текста и даты создания. Это гарантирует идемпотентность импорта и 100% совпадение идентификаторов в СУБД и поисковом индексе.
2. **Сортировка по новизне (ТЗ):** Полнотекстовый поиск выполняется движком Elasticsearch. Возвращенные ID передаются в PostgreSQL, где на уровне базы данных выполняется эффективная выборка с финальной сортировкой `ORDER BY created_date DESC LIMIT 20`.
3. **Русская морфология вместо английских дефолтов.** Поле `text` разбирается кастомным анализатором `ru_text` (`app/scripts/init_db.py`), потому что стандартный `standard` анализатор на русских данных работает почти вслепую:

   | Что сделано | Зачем |
   |---|---|
   | `stemmer` с `language: russian` | Сводит словоформы к основе |
   | `char_filter` `ё → е` | «ежи» и «ёжи» иначе разные токены |
   | `char_filter` омоглифов `A→а`, `o→о`, `e→е`… | `Apтeма`, `Bacилий`, `oгнём` — это отдельные токены, т.к. буквы совпадают в кириллице и латинице |

## Быстрый запуск
0. Устанавливаем зависимости
   ```bash
   pip install -r requirements.txt
   ```
2. Поместите ваш исходный файл с данными в папку проекта по пути: `data/posts.csv` (в репозитории он уже лежит под этим именем)
3. Запустите сборку и поднятие контейнеров одной командой:
   ```bash
   docker-compose up --build
   ```
4. Docker автоматически дождется полной готовности и прохождения проверок со стороны PostgreSQL и Elasticsearch. После этого автоматически отработает скрипт миграций и импорта CSV `app/scripts/init_db.py`, а затем запустится веб-сервер.

Сервис будет доступен по адресу: [http://localhost:8000](http://localhost:8000)
Интерактивная документация Swagger (OpenAPI): [http://localhost:8000/docs](http://localhost:8000/docs)

## Запуск тестов
Чтобы запустить функциональный тест-пакет внутри поднятого контейнера приложения, выполните команду:
```bash
docker exec -it search_api pytest tests/
```

В наборе есть регрессионные тесты на русскую морфологию (`test_search_russian_morphology`) и на латинские омоглифы в словах (`test_search_latin_homoglyphs`)

## Генерация статического файла документации docs.json
Файл `docs.json` лежит в корне проекта и соответствует схеме, которую отдаёт `GET /openapi.json`. Для обновления спецификации выполните:
```bash
curl http://localhost:8000/openapi.json -o docs.json
```

## Фронтенд (необязательно)

По заданию фронтенд не требуется, поэтому сервис `frontend` в `docker-compose.yml` объявлен за **compose-профилем** и обычной командой `docker compose up --build` **не поднимается**. Бэкенд при этом остаётся ровно таким, как в описании

Включить интерфейс:
```bash
docker compose --profile frontend up --build
```
После этого UI будет доступен на [http://localhost:5173](http://localhost:5173).

Выключить (уже запущенный фронтенд):
```bash
docker compose --profile frontend stop frontend
```

Что умеет UI: поиск по тексту документа, выдача с карточками (дата создания, id, рубрики, текст с обрезкой и раскрытием), удаление документа прямо из выдачи, состояния загрузки/ошибки/пустого результата.
```bash
cd frontend
npm install
npm run dev
```
